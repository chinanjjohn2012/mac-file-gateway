## 3. Before LOAD: fail-closed linker output checks (P3-02)

The actual **final linked** image is inspected, not only the upstream `.o`. `file -b` must recognize Darwin **Mach-O 64-bit arm64** or Linux **ELF64 x86-64 ET_DYN shared object**; unknown CPU/ABI is BLOCK.

- **External symbol and imports:** `nm -u` must report **zero undefined symbols**. `nm -g` must match **exactly one** defined strong text export: Darwin `_c3b03_t01_no_signal_candidate` or Linux `c3b03_t01_no_signal_candidate`. Other names, suffix/prefix aliases, weak/undefined/data types and a second export are BLOCK. Linux also requires `nm -D --defined-only` to show the same exact export; Darwin verifies `nm -m` has no weak external alias.
- **Linux:** `readelf -hW` and `-lW` verify ET_DYN and no interpreter; `readelf -dW` and `-SW` reject any unexpected shared dependency (`DT_NEEDED`), RPATH/RUNPATH, INIT/PREINIT/FINI arrays and PLT/GOT loader surfaces. `readelf -rW` must prove **no final runtime relocations**. `objdump -dr` must not show syscall/trap or unresolved indirect call/jump targets.
- **Darwin:** `otool -l` verifies the linked image's own `LC_ID_DYLIB`; forbids `LC_LOAD_DYLIB`/weak/reexport, loader path fallback (`LC_RPATH`), `__mod_init_func`, `__interpose`, lazy symbol pointer/initializer sections and other unapproved loader/import commands. `otool -L` must expose only the artifact's own ID (no libSystem or other dylib). `otool -rv` must have no nonzero relocation entries; `otool -tv` must not include trap or unreviewed indirect branch. Unknown/unparseable architecture data, extra export, dependency, initializer, relocation, trap or indirect target yields a **real failing test**.
- Strong vs weak and alias checks are **exact equality**, not substring matching. This is intentionally a small and restrictive initial allowlist. If a real Darwin/ELF linker needs runtime imports or relocations, **STOP** and request a new independent safety review of an explicit allowlist; do not quietly relax this R1 gate.

**Genuine negative linked artifacts:** The tests separately build (without loading) synthetic local C *mutants* with a prefix/suffix exported alias, a second exported function, a weak exported function and an initialization constructor. Every mutation must be rejected by inspection **at/before PRE-LOAD**. These are compile/link artifacts only, with no system API and no signal path; testing a constructor's mere presence never triggers it by loading.

## 4. Artifact custody and limits

A `tempfile.TemporaryDirectory` creates a fresh owned `0700` root; all paths are resolved to its canonical identity, verified by `lstat` to be non-symlinks and owned by this process. The reviewed final regular library must have `st_nlink == 1`, and is made read-only `0400`. A trusted file descriptor with `O_NOFOLLOW` (where available) is opened, `fstat` matches path `lstat` dev/inode/size, and final library SHA256 is calculated from that descriptor. Afterward inode/size identity is rechecked; the temporary directory is automatically removed after the test. These facts are pre-load **preparatory** controls, not a demonstration that a future multi-process loader can atomically bind a library: TOCTOU/loader-path verification still belongs to separately reviewed R2 source/Adapter custody.

There is **NO dynamic load** in R1. A .dylib/.so can itself have initializers that would run at load; their absence must be verified **before** any future `ctypes.CDLL`/`dlopen`. No post-load SHA check can repair an unverified initializer.
