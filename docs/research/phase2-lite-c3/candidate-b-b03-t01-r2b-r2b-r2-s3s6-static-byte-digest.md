## Purpose

The earlier S6 validator recomputed S0→S3 canonical SHA digest chains using object SHA and linked SHA observations but deliberately did not retain the **actual linked library and object raw byte contents** as independent hash inputs. This substage binds each observed hash to a **bounded fresh same-session nofollow-FD byte snapshot** while retaining all NO LOAD restrictions:

1. S3 keeps the existing immutable Candidate C input, fixed compile/link flags, sanitized ENV, real ephemeral `.o` and `.dylib/.so`, and static file/nm/otool/readelf/objdump inspection. It adds a bounded (`1 MiB` maximum, strictly nonempty) `os.open(O_NOFOLLOW|O_CLOEXEC)` read of the already-produced **object** and **linked library**. `fstat` identity (dev/inode/uid/nlink/mode/size/mtime/ctime) is checked against the original stat, checked again after the read and compared with the current path. SHA256 of the read bytes must equal the original nofollow-FD hash. The linked header captured for Mach-O/ELF metadata validation must equal the start of the **same in-memory linked image byte array**. Temporary object and library are still deleted when the S3 collector finishes.
2. The raw byte snapshots are retained **only in the local test process in-memory S3 evidence**, not dumped to CI console or uploaded as artifacts. The existing S3 printed JSON explicitly excludes raw `object_bytes`, `linked_image_bytes` and `image_header_bytes`; only sizes and SHA digests are printed. The blobs are inert research artifacts, never loaded, FFI-bound or called.
3. S6 requires the two actual `bytes` fields and enforces nonzero bounded lengths, recomputes both SHA256 values directly from the supplied bytes, verifies the linked header equals the first `4096` bytes of the linked snapshot, and then checks the already reviewed S0→S1→S2→S3 canonical stage chain, static linked-header metadata, S4 ABI/AST and unrelated inert S5 DATA checks. Missing, mutated, wrong-typed, oversized or inconsistent bytes, or valid-format rehashed SHA with the original bytes, yield exactly `REJECT`; a consistent **partial evidence** bundle yields at most `REVIEW_REQUIRED_NO_LOAD`.
4. Dedicated regressions include wrong digest, header-byte disagreement, valid 64-hex digest recomputed into the S0→S3 chain without matching raw object/linked bytes, file symlink/hardlink, owner-mode change after observation, empty/oversized data and missing raw evidence. Genuine S3 object/linked byte SHA, file snapshots and in-memory header prefix are checked on macOS ARM64 3.13/3.14 and Linux x86_64 3.13. The test still proves a **fabricated but fully internally self-consistent** replacement byte snapshot and recalculated digest chain can produce `REVIEW_REQUIRED_NO_LOAD` — NOT `ALLOW`, independent provenance, or safe C loading.

**This is NOT a new assurance of immutable provenance.** Byte snapshots are made at particular times with a private ephemeral build directory and closed FDs; a same-UID writer or concurrent substitution could change a path between observations. There is no atomic link from source/compiler or the observed `.so/.dylib` inode to any future dynamic loader, no proof that external linker tools consumed the same inode, no validation of whole-file machine CFG, no complete import/fixup/initializer proof and no real Python FFI import/call. In particular S5 observes a **different inert non-executable DATA file**, not the S3 image, and these collectors use separate temporary sessions. Hashes and reported bytes are ordinary untrusted test evidence and do not authenticate their provenance. Do not claim any D1 full gate closed from this work.
