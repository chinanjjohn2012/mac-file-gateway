### 5.1 GOFLAGS and executable toolhook: closed child environment, mandatory PRE-SPAWN deny

This is NOT a verified exploit of current ordinary F1, which still denies positive execution.

For a NEW authorized T1 fixture or a future reviewed product launcher, the only accepted effective Go child environment is a FRESH mapping constructed from an explicit reviewed allowlist, **not** `os.environ.copy()`, a filtered host `PATH`, a shell-inherited `GO*` namespace or a later Go process observation. The proposed T1 exact allowlist is `HOME`, `TMPDIR`, `LANG`, `LC_ALL` (fixed to reviewed values), `PATH` (fixed order of checked private staged tool paths and a separately reviewed minimal OS baseline), `GOROOT` (checked private Go 1.27.3), `GOTOOLCHAIN=local`, `GOENV=off`, `GOFLAGS=""`, `GOPROXY=off`, `GOSUMDB=off`, `GOWORK=off`, `GO111MODULE=on`, `CGO_ENABLED=0`, `GOPATH`, `GOMODCACHE`, `GOCACHE`, `GOTMPDIR` (all checked private absolute directories). ### 5.3 Enforceable network/source boundary BEFORE any T1 foreign code

B102-P2-DESIGN-03: `GOPROXY=off`, `PIP_NO_INDEX=1`, offline wheelhouses, a URL monitor after the request or GitHub-hosted network alone do NOT prevent arbitrary compiler/third-party code or its background descendants from contacting an unintended host first. Product `local_best_effort` is explicitly trusted-code/no-sandbox; the tighter isolated native-T1 source-qualified assertion needs a separate, enforceable test-environment control, not a global F3 promise.

Proposed **Gate B default is OFFLINE_ONLY**: (1) perform already approved exact-source archive acquisition through the known restricted official HTTPS origins BEFORE native T1, preserving original source SHA, URL hops and immutable input paths; (2) switch to an independently verified enforceable egress-deny execution domain (runner-owned isolated VM/network namespace or an equivalently audited host/network policy that applies to all native children AND descendants), denying outbound TCP/UDP/DNS and unexpected proxies BEFORE the first Go/Pipenv executable can start; (3) retain evidence of that policy's enforcement attachment to the actual child context, including a separately authorized non-destructive canary/proof of rejected outbound attempts from that same context before executing any foreign code; (4) if this isolation/proof is absent or cannot be safely prepared on disposable macOS 15 ARM64, fail closed, report `T1=NOT_RUN / EVIDENCE_STATUS=INSUFFICIENT`, and DO NOT turn on Go/Pipenv or use a weaker environment-only fallback. No unapproved `pf`, system firewall or shared runner configuration changes are implied by this design.

An alternative `BOUNDED_EGRESS` profile would require NEW specific owner consent **before** any execution: exact outbound host/IP+port, byte/time request budgets, trusted per-process precontact allowlist enforcement attached before the first instruction of Go/Pipenv or descendants, original request/deny evidence, a monitor able to stop NEW admissions and safely revoke EGRESS on violating the allowed scope, and a deterministic failure/status policy. A post-contact log, a bare proxy variable, or `cancel`/unknown PID kill is insufficient. If no enforcement capability exists, this profile is DISALLOWED. Revoking network permission is not permission to kill a process; ambiguous child/owner state still latches unavailable with NO unqualified PID/PGID signals. No traffic to an unapproved host may be treated as a tolerable test anomaly.

This egress scope is required only for claiming the isolated SOURCE-CLOSED native T1 evidence under a future owner-approved profile. It does NOT claim the future ordinary trusted-local product is sandboxed or deny all legitimate user-chosen project network actions. Even in a true offline T1, arbitrary filesystem/process side effects and last-moment same-UID executable path races remain separately classified risks.
