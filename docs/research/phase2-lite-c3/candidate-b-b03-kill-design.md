**Research question:** In a *newly created, test-only* Candidate B process tree, can the sole Native Owner perform TERM → *at most one* forced group SIGKILL against a **still-valid, still-held** Anchor PGID after a real TERM-resistant Worker remains ARMED, while the **group-external Controller survives**, as Worker's only lawful parent obtains actual `waitpid` evidence, and Owner separately reaps Anchor and Controller, verifies owned FDs, and stops all group signaling even on failure? **This is not a G2 safety qualification**, not proof of atomic PGID authorization, and not permission to signal an existing host group.

## 1. Parentage, permitted actors and frozen test-only boundary

```text
Gateway / GitHub Actions (not a process-group signaler)
└── Native Owner Helper  [one serialized state machine; only group signaler]
    ├── Anchor           [test-owned, unreaped group leader; PID = target PGID]
    ├── Controller Relay [separate self-led PGID, same verified session]
    │   └── Worker       [Controller's direct child, joins Anchor PGID pre-gate]
    │       └── optional known synthetic descendant [T10, joined target group]
    └── optional Canary  [independent self-led group, same test-owned session]
```

- Owner alone creates/holds/waits Anchor, Controller and Canary. Controller alone creates, **waitpid**-reaps Worker; only Worker's legitimate parent may claim `OBSERVED_EXIT(code)` or `OBSERVED_SIGNAL(SIGKILL)`. A known grandchild may be observed via a separately established native watcher, **not** assumed waitable by Owner. No SIGCHLD callback, other waiter, async child watcher or handler configured with `SA_NOCLDWAIT` may race the designated direct-child waiters.
- Owner and Controller remain *outside* the target Anchor PGID. Before **every** eligible group signal, Owner must independently verify Anchor is its live, unreaped direct child and group leader; Controller is Owner's still-live direct child, `getpgid(controller_pid)==controller_pid` and shares the expected Session; Controller/Worker's typed identity, Worker parentage, expected Session and target PGID are independently checked. C1/C2/B01/B02 results are prior evidence, **not substitutes for these checks on the actual B03 task**.
- Only the research Driver may select **fixed enumerated modes**; no parameter for caller-supplied PID, PGID, command, binary, environment, user Workspace or path. The Driver creates a fresh owned `0700` private test root, bounded synthetic child programs and an independent Canary. No product runtime integration; only a checked, newly created group may ever receive real `kill(-pgid,SIGKILL)`.
- Controlled children have explicit birth/READY/ARMED and cooperative exit gates, independent self-expiry bounds, and explicit `SIGCHLD=SIG_DFL`, no `SA_NOCLDWAIT`. Owner and Controller have a fail-closed SIGPIPE/EPIPE strategy. **The independent B-03 Anchor Helper must actively install `SIGTERM=SIG_IGN` via `sigaction` and natively verify it *before* its trusted READY; inherited disposition or B-02 history is not acceptable proof. It must recheck its own disposition through a trusted post-TERM observation gate.** Its self-expiry is set after the entire valid TERM→grace→KILL admission window (while allowing the test to finish within the immutable `outer_deadline`). Worker receives deliberately **TERM-resistant** state (proved with `sigaction` / `sigprocmask`) but SIGKILL does not depend on restoring TERM to default; positive study must prove the Worker is still live and in the intended group immediately before escalation.
- Real Darwin call paths are mandatory for positives, not only mocked `kill` or string markers. **All stale-PGID, omitted-gate and unauthorized-call fault variants must intercept before a real negative-PGID syscall.** No real SIGKILL may target an invalid, inherited, user-supplied or unverified PGID. A test marker or ticket is correlation/experimental timing, never a kernel capability or trusted Worker exit status.

## 2. One Owner state machine, signal ordering and non-extendable lifetime

```text
NEW → OWNED_ANCHOR_HELD → WORKER_JOIN_VERIFIED → WORKER_ARMED
    → TERM_ELIGIBLE → TERM_ATTEMPTED / TERM_SENT
    → GRACE_RUNNING / WORKER_STILL_LIVE
    → KILL_ELIGIBLE → KILL_ATTEMPTED [successful or failed] → SIGNALS_CLOSED
    → CONTROLLER_WORKER_WAITED | WORKER_UNKNOWN
    → OWNER_ANCHOR_CONTROLLER_REAPED → FDS_CLOSED
    → cleanup VERIFIED | UNRESOLVED

Loss of owner identity, READY, direct parentage, native waiter or IPC;
deadline exceeded; unexpected Worker/Anchor/Controller exit
    → refuse any new group signal → SIGNALS_CLOSED
    → legal, bounded, *cooperative* own-child cleanup
    → SAFE_REFUSAL or BLOCK / UNRESOLVED according to evidence
```

1. **Exactly one serialized signal/reap lane.** All group TERM and group KILL admissions and Anchor's final `waitpid` pass through the same Native Owner lane. Until it closes `SIGNALS_CLOSED`, nobody may consume Anchor's wait status. `waitpid(WNOHANG)` is a consuming operation when it returns the child PID; if Anchor is actually exited/reaped, **KILL eligibility ends** even if a stale PGID remains numerically equal. `ECHILD` is fail-closed; never reinterpret a zombie or missing waiter as a live Owner-held group.
2. **TERM-resistant Worker and TERM-surviving Anchor are *both* mandatory native preconditions.** Before ARM/TERM, the newly created Anchor itself installs and verifies `SIGTERM=SIG_IGN` using `sigaction`, sends a private trusted READY bearing that native observation, and stays Owner-held/unreaped with `PID=PGID` and expected SID/PPID. Controller deliberately configures Worker to ignore or block TERM and verifies that native state at READY. Owner issues **at most one** authorized `kill(-owned_pgid,SIGTERM)` as in B-02 and checks syscall success. At a deterministic post-TERM barrier and after a real bounded grace, the Anchor must **re-verify its native `SIGTERM=SIG_IGN`** and report it via its sole private control channel, while Owner independently observes the Anchor as a **live** (not zombie/reaped) owned direct-child group leader with unchanged PID/PGID, SID and PPID. Owner likewise independently verifies Controller still owns the Worker-wait role and Worker is still alive/in-group. Neither a successful group TERM syscall nor an old READY proves post-grace survival. Missing/incorrect Anchor disposition, absent native post-TERM observation or premature Anchor exit means **no group KILL**, with honest `SAFE_REFUSAL/BLOCK` and a separate cleanup axis. Anchor's synthetic self-expiry bound must extend beyond the maximum lawful TERM→grace→KILL admission interval; do not rely on inherited handlers or fixed sleeps.
3. **KILL admission and closure.** Owner's single `send_kill_to_owned_group()` checks its native held Anchor, Controller self-led outside group, verified Worker membership/parentage (and any explicitly required known descendant), Owner state, inherited task binding, and derived deadlines **at the signal entry point**; it increments `kill_attempts` **before** the syscall. On **first attempted** group KILL, successful or failed, the Owner must transition irreversibly to `SIGNALS_CLOSED`; **no second group TERM/KILL, retry on ESRCH/EPERM/EINTR, or subsequent numeric PGID fallback**. The group SIGKILL may kill Anchor and Worker; Owner must close signal authority **before** reaping Anchor or handling its exit. `KILL_ATTEMPTED`, `KILL_SENT`, `kill_errno_class` and observed Worker/Anchor outcomes are **separate**.
4. **One immutable monotonic outer deadline, staged reserve and positive KILL-entry margin.** Freeze a single `outer_deadline` at task creation, a strictly positive `cleanup_reserve_ms` large enough for lawful Controller Worker wait, Owner's Anchor/Controller/Canary reaps and all controlled FDs, a positive `term_grace_ms` and **strictly positive `kill_entry_margin_ms`** for post-grace identity checks and KILL admission. Derive `kill_admission_cutoff = outer_deadline - cleanup_reserve_ms` and **`term_admission_cutoff = kill_admission_cutoff - term_grace_ms - kill_entry_margin_ms`**; assert the term cutoff leaves adequate startup/ARMED time. TERM must occur strictly before its cutoff, so `grace_end = term_sent_at + term_grace_ms` leaves a **positive native-check/KILL-entry margin** before `kill_admission_cutoff`; post-grace event and native Anchor/Controller/Worker checks consume this reserved margin, not a second deadline. KILL is eligible only after confirmed grace completion and with `now < kill_admission_cutoff` and `now < outer_deadline`. If `grace_end >= kill_admission_cutoff` (including equality), the experiment must refuse KILL, count zero KILL attempts and use only lawful cooperative cleanup within the **original** deadline; no clock reset, KILL retry or additional cleanup window. A dedicated boundary test must exercise equality and late admission with a test-only event barrier. If cleanup overruns `outer_deadline`, report `BLOCK/UNRESOLVED`, never VERIFIED.
5. **Before/after identity observation is not atomic.** `getpgid/getpid/getsid/proc_pidinfo` then `kill(-pgid,...)` is not a kernel-atomic capability. A still-unreaped process does not by itself prove every XNU PID/PGID reuse or group-retention property; match exact hosted kernel version to XNU process/PGRP allocation/reap source and document the proof boundary. If that chain is missing, the experiment may be `PARTIAL_B03_NATIVE_NOT_G2` but **not** product-qualified. After KILL, Anchor identity no longer authorizes further group signaling, regardless of `waitpid` outcome.
6. **If Worker exits during grace**, do not automatically declare `OBSERVED_SIGNAL(SIGKILL)` or force KILL anyway. In a deliberately limited T02 mode, Controller reports its already-consumed legitimate Worker `waitpid` result; Owner closes group authority and cooperatively retires Anchor. The separate “Worker exited but a known descendant remains in-group” question is T10 and must track descendant membership/exit independently before drawing any group-cleanup conclusion.
7. **T08 has two distinct admission stages, never one blended verdict.** A Controller that starts with the wrong self-led PGID fails the *TERM* gate before a lawful TERM and cannot be counted as KILL-gate coverage (T08a). A Controller that initially satisfied TERM admission but **actually exits after TERM** loses its legal Worker-wait relationship; Owner then enters the *real KILL gate* after a deterministic event and receives a refusal with zero KILL attempts (T08b). The latter is necessarily Worker `UNKNOWN` / cleanup `UNRESOLVED` even if controlled synthetic process exits are independently observed; it is not a `SAFE_REFUSAL/VERIFIED` result. Never attempt to simulate a live Controller group-leader changing its own PGID after TERM, or to turn a reported/IPC-only anomaly into native identity loss.

## 3. Result truthfulness, IPC ownership, FD and cleanup evidence

Freeze **two independent result axes** and a separate action ledger:

- `worker_result = OBSERVED_EXIT(code) | OBSERVED_SIGNAL(signum) | UNKNOWN`. For Worker SIGKILL, only the Controller's exact, legitimate `waitpid(worker_pid,...)` with `WIFSIGNALED && WTERMSIG == SIGKILL` permits `OBSERVED_SIGNAL(SIGKILL)`. `kill()==0` alone, Anchor's `waitpid`, stdout/EOF, `128+SIGKILL` and a private test fault marker **cannot** prove Worker status. If Controller dies before wait, or after wait but before its legally sourced Final reaches Owner, Owner records `UNKNOWN`; the former can leave orphaned unknown Worker state and cannot be called verified cleanup.
- `cleanup = VERIFIED | UNRESOLVED`: Owner needs actual Owner-side `waitpid(Anchor)` with `WIFSIGNALED && WTERMSIG==SIGKILL` for a successful target KILL observation, lawful Controller reap, evidence that Controller legally waited/reaped Worker, verified independent Canary/known-descendant observations where applicable, successful **checked** close of all owned Control/Worker/Anchor/Controller/Canary/root-directory FDs and `now < outer_deadline`. `cleanup=VERIFIED` is only for the **explicitly enrolled synthetic process set**, not arbitrary descendants or a whole host process tree. Loss of a Final or any FD close error => `UNRESOLVED`, even if Owner's direct children actually exited. Never hide Actions orphan cleanup.
- `action_ledger = TERM_ATTEMPTED / TERM_SENT / KILL_ATTEMPTED / KILL_SENT / SIGNALS_CLOSED`; keep pre-syscall **attempt counters** and success/failure/errno-class separately, including ESRCH/EINTR/EPERM. No action can replace `waitpid`. Any signal after `SIGNALS_CLOSED` must be detected as a contract violation; **do not actually send unsafe fallback signals in negative tests**.
- Use a dedicated test-Owned control IPC endpoint with framed/versioned bounded messages and unique sequences `WORKER_READY`, `WORKER_ARMED`, `WORKER_REAPED`, `FINAL/UNRESOLVED`. The Controller is the only trusted Worker-status writer; Worker must **not** inherit its trusted control writer (check CLOEXEC plus explicit spawn file-actions, duplicated FDs and half-close tests). A ticket is correlation not authentication. Owner commits one terminal; forged stdout frames, duplicate/replayed FINAL, broken pipe, Controller loss and maliciously timed EOF must fail closed. T08/T09 check that controlled test audit markers prove timing only, never substitute for Worker wait evidence.
- SIGKILL and TERM can interact with pipe closing, dead Controllers, blocked waits and Child self-expiry. Every test has a **single original deadline** and an explicit cooperative fail path (only where its own named group can be legitimately controlled). **Before T04, T08b or the escaped-descendant T10 control is permitted to run**, require a separately approved synthetic orphan-lifecycle plan: exact known PID(s), a genuinely independent native exit observer registered **before** loss/escape, a test-created self-expiry/exit gate whose bound falls inside the single `outer_deadline`, and explicit evidence that no Actions runner orphan cleanup is needed. Independent NOTE_EXIT/self-exit is **not** a lawful Worker `waitpid` after Controller death and cannot make cleanup VERIFIED. If that containment proof is not available, **do not start the mode**: report `NOT_RUN / BLOCK` rather than leaving an orphan or masking it via extra signals. Do not use direct PID KILL on uncertain identity, forced runner cleanup, recursive host process scans or unsafe orphan signaling to make CI pass.

The only real SIGKILL permitted by a positive experiment is on a freshly generated and still-Owner-held group. The negative/mutation cases use no-signal interceptors when authority is uncertain.

**Mandatory RED/MUTATION tests** (separate temporary test binaries, no modified protected source or real stale-PGID kill):
- Omit Anchor live/parent identity check **only with an intercepting no-signal stub**: B03-T03 must detect would-be unauthorized KILL attempts **even on simulated ESRCH**.
- Omit Controller `SETPGROUP` / Owner TERM-admission check: **T08a** must catch the real bad-creation PGID before TERM (not claim KILL testing). Separately omit Owner's Controller-live/parent/PGID **KILL-admission** check **only** in the real-loss T08b test variant and intercept any would-be KILL with a required no-signal stub; native `kill(-pgid,SIGKILL)` must never run with lost Controller eligibility.
- Replace Controller legal Worker `waitpid` evidence with fabricated `KILL_SENT`, stdout or audit marker: strict Driver must reject `OBSERVED_SIGNAL(SIGKILL)`.
- Remove `kill_admission_cutoff` or allow a second group KILL: B03-T07 / one-shot mutation must be rejected **without issuing an unsafe real signal**.
- Fake a successful FD close, duplicate an IPC writer into Worker, or remove a legitimate `WORKER_REAPED` frame: Driver/Owner must return **BLOCK/UNRESOLVED**, not VERIFIED.
- **Red eligibility requirement:** native positive T01 must require both Anchor's real `SIGTERM=SIG_IGN` setup/READY and post-grace native disposition + owned live PID/PGID/SID/PPID observation, *as well as* real Worker survival after TERM and a strictly positive `kill_entry_margin_ms`; removing or corrupting Anchor setup/post-TERM witness must block KILL. A simple successful `kill(SIGTERM)` response, Worker voluntary exit or fake Controller wait message is not sufficient. Equality at `kill_admission_cutoff` must be an independent zero-KILL negative boundary. Otherwise `NOT_RUN / BLOCK`.
