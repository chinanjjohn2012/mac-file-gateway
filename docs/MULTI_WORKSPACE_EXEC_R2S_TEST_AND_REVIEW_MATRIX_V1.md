## 1. Risk profiles and evidentiary honesty

- **T0:** Pure state/consent/fake lifecycle, deterministic faults, no host process, no signals, no persistent user data. The future R2-S code may be exercised only after applicable design/implementation authorization. This document itself runs no tests.
- **T1:** Exact disposable private filesystem, real owner lock, genuine REST + official MCP, real *separately authorized* Git and File Write, no positive Multi Exec. Non-destructive and environment-limited; ensure loopback and current isolation before executing a future test.
- **T2:** Real macOS native leader/PGID, process termination, crash/restart, observed detach, signal identity/collateral checks, VM stop: **NOT_AUTHORIZED**. Requires new explicit resource inventory, external watchdog, process/time/memory/storage budgets, preapproved stop identity and recovery procedure, user approval. T0 fake success never replaces T2 safety proof.
- **T3:** Current user Mac, Tunnel, shared/production resources or production deployment: **NOT_AUTHORIZED** independently of T2.
- **CI/identity:** GitHub current Head/Base/Tree and full committed file set; record actual original Run/Job/log, RED/FAIL/SKIP/NOT_RUN. G05 tracks source/Manifest and unchanged R004 36-wheel+RECORD scope; do not claim all source outside RECORD assessed. Head and synthetic Merge are distinct execution identities even when Tree matches.

## 4. Review criteria for this design stage

B Standards and C Spec independently inspect the exact proposal Diff and referenced frozen contracts, not developer summary. They must independently challenge:
- Proposed D0 limited exception against existing §0.4 full-descendant rule; separation from Strict/F3 and private test grant.
- Candidate A mutable-code trust, altered Git/File/Pipenv without implicit reapproval; root, scope, backend, record version and operator consent boundaries.
- Known surviving detached child vs unobserved possibility, resource accumulation and absence-of-evidence trap.
- Identity-safe at-signal macOS behavior and resulting no-signal/UNKNOWN gate if no supported primitive.
- State ordering/crash windows, duplicate spawn/ACK loss, v1/v2/downgrade, private FD and owner lock, quota/accounting.
- Actual F1 REST/MCP and legal Git/File remain unaffected; client cannot select capability or unquarantine; status truthful.
- Scope and feasibility: Design TARGETED PASS is not product code FULL or integration PASS; unapproved T2/T3 cannot be run to fill evidence.

**NO-GO:** real process launch or signals on user Mac, forced Gateway crash on shared host, Native C/C3, VM experiment, user Tunnel, production deployment/tag/config, automatic UNKNOWN recovery.
